# WHY

oneclaude runs every Claude subscription account a person has as one pool: a CLIProxyAPI plugin places each Claude Code agent on an account, and a cmod mod shows the pool's status under the prompt.

# Facts

- `cli/` is the Go module: the CLIProxyAPI plugin at its root, a library built with `-buildmode=c-shared`, and the `oneclaude` program in `cmd/oneclaude/`, which embeds that library. It lives in `cli/` because cmod builds, releases, and installs a mod's program from there. `make -C cli build` writes `.target/dist/oneclaude-v<version>.dylib`, `make -C cli dist` writes `.target/release/oneclaude-darwin-arm64`, and `make -C cli test` runs every Go test. Each first copies the library to `cli/cmd/oneclaude/oneclaude.dylib`, which git ignores and the program's `go:embed` needs, so a bare `go test ./...` fails before a build.
- The Makefile runs the `go` on `PATH`, or the one `GO=` names.
- `package.json` `cmod.program` names `oneclaude`, and `cli/package.json` names `make dist` as its build, so `cmod publish` attaches `oneclaude-darwin-arm64` to each GitHub release, `cmod install` downloads it, and `cmod link` builds it from the checkout.
- A push to `main` runs `.github/workflows/ci.yml`, which tests and, when the tag `v<version>` is missing, runs `cmod publish`. `docs/releasing.md` holds the steps.
- The proxy loads a plugin from `<plugins.dir>/darwin/arm64/<id>-v<version>.dylib`, and the plugin id `oneclaude` comes from that file name. A plugin with no `plugins.configs.oneclaude` block in the proxy config stays off.
- The proxy picks up a new plugin file only on a config reload or a restart, and then hot reloads it with no dropped reply. It deletes older versions of a plugin's file at startup. Never overwrite a loaded library in place: copy the new build under a new version name.
- The proxy loads the version `plugins.configs.oneclaude.store.version` names, as its Plugin Store does. cmod runs `setup/install.sh` on install and on every new version: it runs `oneclaude install`, which writes its embedded library into the proxy's plugin folder and sets that key, so a version bump in `cli/main.go` and `.claude-plugin/plugin.json` together, then `cmod link .`, takes a build live.
- `oneclaude install` finds the proxy config from the `-config` of the process on `ANTHROPIC_BASE_URL`'s port, else Homebrew's `etc/cliproxyapi.conf`, and rewrites only the config's `plugins` and `management` blocks, leaving every other byte as it was. With no proxy found, it installs CLIProxyAPI with Homebrew, sets its `server.host` to `127.0.0.1`, drops the example's placeholder `access.api-keys`, and starts it with `brew services`.
- The config keeps the proxy's management key only as a bcrypt hash: the proxy hashes a plain key when it loads the config and writes the hash back. `oneclaude install` sets the key `oneclaude`, as its hash, only on a proxy with none, and marks that in `management-key-was` in the mod's data folder for `oneclaude remove` to take it out. A proxy with its own key keeps it. The install writes the config's path to `proxy-config` in the data folder, where the mod's `management-key` installer step checks the key the person enters against the hash with `bcrypt-ts`, offline. Claude Code's hooks import only relative paths and no Node module, so the mod imports `bcrypt-ts`'s browser build, which imports nothing. It copies the account Claude Code is logged in to, read from `~/.claude.json` and the keychain item `Claude Code-credentials`, into the proxy's auth dir as the credential file the proxy's own login writes, unless a credential there has that email.
- The mod sets `env.ANTHROPIC_BASE_URL` with cmod's `settings.user.update`, a JSON Merge Patch that leaves every other `env` value, once a session after the proxy answers with oneclaude's status. cmod takes back only that value at removal. A base URL the person set to another address stays.
- The plugin reads each Codex account's weekly usage from `chatgpt.com/backend-api/wham/usage`, the window whose `limit_window_seconds` is a week, and `status.json` lists Codex accounts in `codex`, apart from the Claude pool it routes.
- A tmux text capture of Claude Code drops Nerd Font glyphs that Ghostty draws on screen, so a capture never proves a glyph is missing.
- The proxy consults only one scheduler plugin, the first by priority and then by id, so Seat Pacer must be off for oneclaude to route.
- `cli/main.go` and `cli/internal/runtime/{wire,envelope,host}.go` adapt Seat Pacer's MIT-licensed C boundary, credited with its license in `cli/NOTICE`.
- The plugin serves its status without a key at `/v0/resource/plugins/oneclaude/status.json`, with account names cut to the local part of their address.
- Only the proxy knows its blocks (cooldowns), and no host callback lists them, so the mod reads them from `/v0/management/auth-files` with the management key, matched to accounts by `auth_index`. The mod sends a key only once it fits the hash in the proxy's config, because the proxy bans an address for 30 minutes after 5 refused keys, even for the right key after that. `[Unblock]` posts to the plugin's `/v0/management/plugins/oneclaude/unblock`, which calls `host.routing.reset_cooldown` and logs it. The dev proxy's api-key credentials have no auth file, so blocks show only for OAuth accounts.
- The plugin serves `cli/internal/runtime/dashboard.html` at `/v0/resource/plugins/oneclaude/dashboard`, its only resource with a `Menu`. The panel orders a plugin's menu entries by path, so `management.html#/plugin-pages/oneclaude/0` shows the dashboard in an iframe of the same origin. Its Content-Security-Policy names the hash of the page's one `<script>` block, computed when the plugin loads.
- `/v0/resource/plugins/oneclaude/history.json` serves each account's requests per hour and the log for the last 7 days, for the dashboard. `status.json` carries the last 24 hours of the log, which the plugin keeps in `usage.json` and writes back from memory on every save, so an edit to it holds only if it lands just before a new version loads.
- `/v0/resource/plugins/oneclaude/usage.json?period=&by=&units=` serves the finished Usage table: labelled rows sorted largest first, the total, and the last 30 days for the chart. `cli/internal/runtime/usage.go` adds it up from 90 days of requests by local date, account, model, agent type and project, so the mod's Usage section, the dashboard and `[Optimize usage]` only draw it. Each load reads `requests.jsonl` back from its end in the background, and every request since the load counts as it happens.
- `cli/internal/model/prices.go` holds Anthropic's list prices per model, cache writes at the 1-hour rate, and prices each request on its own, because Haiku 5.5 costs 5 times more above 100,000 prompt tokens. A line logged without its model counts as its family's newest.
- `requests.jsonl` lines without `model` come from before 0.5.1. `cli/internal/runtime/backfill.go` fills them in once per log from `session.Records.RecordedBetween`, matching each to the one transcript request with equal tokens within a minute, and gives an unmatched line its family's newest model so later loads skip the log. The backfill goes once every log is past 90 days without such lines. `RecordedBetween` stays for `importTranscripts`, which adds the 90 days of transcript requests before a log's first line once per data folder, under the account "No account recorded", and sets `usage.json`'s `imported`.
- `usage.Log.Rewrite` runs on the log's writer after the lines queued before it, so a rewrite never loses an appended line. Prune is one rewrite.
- Claude Code sends a custom subagent's type as `custom` in `X-Claude-Code-Agent-Type`, so `session.Records` reads the type from `~/.claude/projects/<project>/<session>/subagents/agent-<agent id>.meta.json`, whose agent id is the `X-Claude-Code-Agent-Id` header, and a session's project from the `cwd` its transcript records.
- The dashboard reads oneclaude's routes without a key and the panel's `/v8/management` API with the management key the panel saves in `localStorage` under `cli-proxy-auth`, or else `oneclaude`. The proxy bans an address for 30 minutes after 5 failed key checks, so the page stops at the first refusal.
- `dashboard?open=dashboard` and `dashboard?open=add-account`, opened on their own, save the panel's login with the key `oneclaude` as the panel's Remember password does, unless the panel holds a login already, then open the panel at the dashboard or at its OAuth login page. The panel passes through its login route while it signs in and drops an address's query on the way.
- The plugin keeps `usage.json`, `limits.json`, `agents.json`, `install.key`, and `requests.jsonl` in its `data-dir` setting, which `oneclaude install` sets to the mod's cmod data folder, because the proxy lists every JSON file under its `auth-dir` as a credential. The install moves the files from the folder the config named before, or `~/.cli-proxy-api/plugins/oneclaude`, before it writes the config, so the plugin never reads the real home folder. `agents.json` holds each conversation's account, so a reload keeps its cache.
- The repository root is a cmod mod: `src/mod.tsx` is the `defineMod`, `hooks/register.ts` only registers it, and `tests/` holds its `bun test` suite. `node_modules/@cmodjs/core/docs/` is the cmod documentation for the installed version.
- `cmod check .` runs every check on the mod. It skips `.target/`, so every build output and the dev proxy live there.
- The dev proxy is Homebrew's `cliproxyapi` binary, run from the repository root with `dev/config.yaml`, whose folders are relative to it, on port 8318 against `cli/cmd/fakeanthropic` on port 8319. `ONECLAUDE_DEV_PROXY=1 go test -run DevProxy` in `cli/` checks routing through it, and its subagent test needs 5 minutes since the last run, while the earlier run's agents still count as active.
- `cliproxyapi` run without `-config dev/config.yaml`, even with a flag it doesn't know such as `--version`, loads the live config and deletes the older plugin libraries in its plugin folder.
- The dev proxy serves its management panel only when it starts with `MANAGEMENT_PASSWORD` set, and downloads `management.html` into `dev/static/`, beside its config, on the first visit.
- `README.md` links every page of `docs/`, the user documentation. A change to what oneclaude does for its users changes the page that describes it in the same commit.
- The live proxy on port 8317 serves the Architect's running agents. Plugin builds go to the dev proxy first.

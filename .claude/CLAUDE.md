# WHY

oneclaude runs every Claude subscription account a person has as one pool: a CLIProxyAPI plugin places each Claude Code agent on an account, and a cmod mod shows the pool's status under the prompt.

# Facts

- `cli/` is the Go module: the CLIProxyAPI plugin at its root, a library built with `-buildmode=c-shared`, and the `oneclaude` program in `cmd/oneclaude/`, which embeds that library. It lives in `cli/` because cmod builds, releases, and installs a mod's program from there. `make -C cli build` writes this machine's library to `.target/dist/<os>-<arch>/oneclaude-v<version>.<dylib|so>`, `make -C cli dist` writes `.target/release/oneclaude-<os>-<arch>` for each machine in `CMOD_MACHINES`, or this one, and `make -C cli test` runs every Go test. clang builds the macOS libraries and `zig cc` the Linux ones, so one Mac builds all four. Each copies the machine's library to `cli/cmd/oneclaude/plugin.lib`, which git ignores and the program's `go:embed` needs, so a bare `go test ./...` fails before a build.
- The Makefile runs the `go` on `PATH`, or the one `GO=` names.
- `package.json` `cmod.program` names `oneclaude`, and `cli/package.json` names `make dist` as its build, so `cmod publish` attaches `oneclaude-<os>-<arch>` for every machine `package.json`'s `os` and `cpu` allow to each GitHub release, `cmod install` downloads it, and `cmod link` builds it from the checkout.
- A push to `main` runs `.github/workflows/ci.yml`, which tests and, when the tag `v<version>` is missing, runs `cmod publish`. `docs/releasing.md` holds the steps.
- The proxy loads a plugin from `<plugins.dir>/<goos>/<goarch>/<id>-v<version>.<dylib|so>`, `.dylib` on macOS and `.so` on Linux, and the plugin id `oneclaude` comes from that file name. A plugin with no `plugins.configs.oneclaude` block in the proxy config stays off.
- The proxy picks up a new plugin file only on a config reload or a restart, and then hot reloads it with no dropped reply. It deletes older versions of a plugin's file at startup. Never overwrite a loaded library in place: copy the new build under a new version name.
- The proxy loads the version `plugins.configs.oneclaude.store.version` names, as its Plugin Store does. cmod runs `setup/install.sh` on install and on every new version: it runs `oneclaude install`, which writes its embedded library into the proxy's plugin folder and sets that key, so a version bump in `cli/main.go` and `.claude-plugin/plugin.json` together, then `cmod link .`, takes a build live. `oneclaude install` never replaces a library file already in the plugin folder, so once a version ran here, even as a dev build, a fix goes live only under the next version.
- The pool can run on another machine than a session: the mod reads every address from the user settings' `env.ANTHROPIC_BASE_URL`, `http://127.0.0.1:8317` when unset, kept in `memory.pool` at each refresh. `oneclaude install` counts the pool as here when that URL is unset, loopback, or names an address of one of this machine's interfaces, and with another machine's it prints that it sets up no proxy and only checks the key. cmod 5.0 has no permissions, so the mod fetches any host and writes the setting with no declaration in `package.json`.
- `oneclaude install` finds the proxy config from the `-config` of the process on `ANTHROPIC_BASE_URL`'s port, else Homebrew's `etc/cliproxyapi.conf`, and rewrites only the config's `plugins` and `management` blocks, leaving every other byte as it was. With a base URL other machines can use, such as `http://devbox:8317`, it sets `management.allow-remote`. With no proxy found, it installs CLIProxyAPI, with Homebrew on macOS and on Linux from the newest GitHub release, checked against the asset's `digest`, into `~/.local/share/cliproxyapi/<version>/` with its config at `~/.cli-proxy-api/config.yaml`. It sets `server.host` to `127.0.0.1`, or to this machine's address a shared base URL names, drops the example's placeholder `access.api-keys`, and names `plugins.dir` from home, because the example's relative `plugins` resolves against each program's working folder. It starts the proxy last, after the config and login are in place, because a proxy started first can miss a change made before its file watcher runs: with `brew services` on macOS and the systemd user service `cliproxyapi` on Linux.
- The config keeps the proxy's management key only as a bcrypt hash: the proxy hashes a plain key when it loads the config and writes the hash back. `oneclaude install` sets the key `oneclaude`, as its hash, only on a proxy with none, and marks that in `management-key-was` in the mod's data folder for `oneclaude remove` to take it out. A proxy with its own key keeps it. The install writes `oneclaude` to `management-key` in the data folder once the proxy takes it, checked against the config's hash or, for a pool on another machine, with one request, and leaves a key already there. The mod sends only that file's key, because the proxy bans an address for 30 minutes after 5 refused keys, and empties the file at a 401, so the `management-key` installer step asks again and checks the key the person enters with one request. It copies the account Claude Code is logged in to, read from `~/.claude.json` and the keychain item `Claude Code-credentials` on macOS or `~/.claude/.credentials.json` on Linux, which hold the same JSON, into the proxy's auth dir as the credential file the proxy's own login writes, unless a credential there has that email.
- The mod sets `env.ANTHROPIC_BASE_URL` with cmod's `settings.user.update`, a JSON Merge Patch that leaves every other `env` value, once a session after the proxy answers with oneclaude's status, unless the value is already set. Each update spawns the cmod program and rewrites `~/.claude/settings.json`, which every running session reloads. cmod takes back only that value at removal. A base URL the person set to another address stays, and the mod shows the pool there.
- The plugin reads each Codex account's weekly usage from `chatgpt.com/backend-api/wham/usage`, the window whose `limit_window_seconds` is a week, and `status.json` lists Codex accounts in `codex`, apart from the Claude pool it routes.
- A tmux text capture of Claude Code drops Nerd Font glyphs that Ghostty draws on screen, so a capture never proves a glyph is missing.
- The proxy consults only one scheduler plugin, the first by priority and then by id, so Seat Pacer must be off for oneclaude to route.
- `cli/main.go` and `cli/internal/runtime/{wire,envelope,host}.go` adapt Seat Pacer's MIT-licensed C boundary, credited with its license in `cli/NOTICE`.
- The plugin serves its status without a key at `/v0/resource/plugins/oneclaude/status.json`, with account names cut to the local part of their address.
- Only the proxy knows its blocks (cooldowns), and no host callback lists them, so the mod reads them from `/v0/management/auth-files` with the management key, matched to accounts by `auth_index`. The proxy checks the key with bcrypt on every request, and `auth-files` takes seconds under load, so the open sessions share one reading in `blocks.json` in the mod's data folder for 14 seconds, and the line draws before the blocks arrive. `[Unblock]` posts to the plugin's `/v0/management/plugins/oneclaude/unblock`, which calls `host.routing.reset_cooldown` and logs it. The dev proxy's api-key credentials have no auth file, so blocks show only for OAuth accounts.
- The plugin serves `cli/internal/runtime/dashboard.html` at `/v0/resource/plugins/oneclaude/dashboard`, its only resource with a `Menu`. The panel orders a plugin's menu entries by path, so `management.html#/plugin-pages/oneclaude/0` shows the dashboard in an iframe of the same origin. Its Content-Security-Policy names the hash of the page's one `<script>` block, computed when the plugin loads.
- `/v0/resource/plugins/oneclaude/history.json` serves each account's requests per hour and the log for the last 7 days, for the dashboard. `status.json` carries the last 24 hours of the log, which the plugin keeps in `usage.json` and writes back from memory on every save, so an edit to it holds only if it lands just before a new version loads.
- `/v0/resource/plugins/oneclaude/usage.json?period=&by=&units=` serves the finished Usage table: labelled rows sorted largest first, the total, and the last 30 days for the chart. `cli/internal/runtime/usage.go` adds it up from 90 days of requests by local date, account, model, agent type and project, so the mod's Usage section, the dashboard and `[Optimize usage]` only draw it. Each load reads `requests.jsonl` back from its end in the background, and every request since the load counts as it happens.
- `cli/internal/model/prices.go` holds Anthropic's list prices per model, cache writes at the 1-hour rate, and prices each request on its own, because Haiku 5.5 costs 5 times more above 100,000 prompt tokens. A line logged without its model counts as its family's newest.
- `requests.jsonl` lines without `model` come from before 0.5.1. `cli/internal/runtime/backfill.go` fills them in once per log from `session.Records.RecordedBetween`, matching each to the one transcript request with equal tokens within a minute, and gives an unmatched line its family's newest model so later loads skip the log. The backfill goes once every log is past 90 days without such lines. `RecordedBetween` stays for `importTranscripts`, which adds the 90 days of transcript requests before a log's first line once per data folder, under the account "No account recorded", and sets `usage.json`'s `imported`.
- `usage.Log.Rewrite` runs on the log's writer after the lines queued before it, so a rewrite never loses an appended line. Prune is one rewrite.
- Claude Code sends a custom subagent's type as `custom` in `X-Claude-Code-Agent-Type`, and no project, so each session's mod sends the plugin a session record, `{session, project, agents, filters}`, to `POST /v0/management/plugins/oneclaude/session` with the management key, which `cli/internal/runtime/record.go` keeps in `sessions/<session id>.json` in the data folder for 30 days. `src/record.ts` sends the whole record as the session starts, at each `onTaskStart`, whose task id is the `X-Claude-Code-Agent-Id`, and at each filter change, one after another, again every second while the pool doesn't answer. The plugin keeps the agents of a session's earlier records, so a reloaded mod loses none, and labels Usage from the record alone.
- The proxy HTML-escapes the strings of a plugin's management answers, so an error the mod shows holds no quote, ampersand or angle bracket.
- The dashboard reads oneclaude's routes without a key and the panel's `/v8/management` API with the management key the panel saves in `localStorage` under `cli-proxy-auth`. The proxy bans an address for 30 minutes after 5 failed key checks, so the page stops at the first refusal. `[Open dashboard]` and `[Add account]` link to `management.html#/plugin-pages/oneclaude/0` and `management.html#/oauth`, and the panel asks for its login the first time.
- The plugin keeps `usage.json`, `limits.json`, `agents.json`, `install.key`, `requests.jsonl`, and `sessions/` in its `data-dir` setting, which `oneclaude install` sets to the mod's cmod data folder, because the proxy lists every JSON file under its `auth-dir` as a credential. The install moves the files from the folder the config named before, or `~/.cli-proxy-api/plugins/oneclaude`, before it writes the config, so the plugin never reads the real home folder. `agents.json` holds each conversation's account, so a reload keeps its cache.
- The repository root is a cmod mod: `src/mod.tsx` is the `defineMod`, `hooks/register.ts` only registers it, and `tests/` holds its `bun test` suite. `node_modules/@cmodjs/core/docs/` is the cmod documentation for the installed version.
- The Architect's sessions run oneclaude linked from this checkout, and cmod reloads every open session after an edit to a linked mod, once its turn ends, so a change under `src/` or `node_modules/` reaches all of them.
- `cmod check .` runs every check on the mod. It skips `.target/`, so every build output and the dev proxy live there.
- The dev proxy is Homebrew's `cliproxyapi` binary, run from the repository root with `dev/config.yaml`, whose folders are relative to it, on port 8318 against `cli/cmd/fakeanthropic` on port 8319. `ONECLAUDE_DEV_PROXY=1 go test -run DevProxy` in `cli/` checks routing through it, and its subagent test needs 5 minutes since the last run, while the earlier run's agents still count as active. Its throttle test cools every Opus credential down, so the filter tests pass only when run apart from it, with `-run DevProxyAFilter`. It sends session records with the key `dev`, so start the dev proxy with `MANAGEMENT_PASSWORD=dev`.
- `cliproxyapi` run without `-config dev/config.yaml`, even with a flag it doesn't know such as `--version`, loads the live config and deletes the older plugin libraries in its plugin folder.
- The dev proxy serves its management panel only when it starts with `MANAGEMENT_PASSWORD` set, and downloads `management.html` into `dev/static/`, beside its config, on the first visit.
- `README.md` links every page of `docs/`, the user documentation. A change to what oneclaude does for its users changes the page that describes it in the same commit.
- The live proxy on port 8317 serves the Architect's running agents. Plugin builds go to the dev proxy first.
- `setup` returns oneclaude's API to other mods, `addFilter` and `removeFilter`, typed in `types/index.d.ts` and following Envoy's `ext_proc`. They change the calling session's record, which starts with no filters as `setup` runs, and reject with the plugin's 400 when a filter's url isn't loopback or `unix:` on the pool's machine. The plugin looks up each request's `X-Claude-Code-Session-Id` in its records. It posts each request in `request.intercept_before`, before the pick, with the path from the request's `Metadata["request_path"]`, each streamed event in `response.intercept_stream_chunk`, where the proxy hands over each Claude event as its own chunk, and each whole response in `response.intercept_after`, which needs the `response_interceptor` capability. All three share the lifecycle `RequestID`, while the usage record's `RequestID` is new per upstream attempt, so a response's filters end at its `message_stop` or `error` event or its whole response. The proxy writes Anthropic's errors without calling any plugin, so filters never see them. The plugin declares schema version 5, so a chunk carries neither the request body nor the chunks before it. A filter's `x-oneclaude-cache-key` header becomes the pick's key, `cache/<value>`, in place of the session's, and is stripped before Anthropic.
- `/accounts` is a Sidebar page, `src/pages/accounts.tsx`. cmod shows a page only once the command or press that asked for it ends, so `page.isOpen` is still false right after `page.toggle()`, and the mod sets its `isOpen` from what it asked, and each refresh from the page.

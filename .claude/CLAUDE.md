# WHY

oneclaude runs every Claude subscription account a person has as one pool: a CLIProxyAPI plugin places each Claude Code agent on an account, and a cmod mod shows the pool's status under the prompt.

# Facts

- `plugin/` is the CLIProxyAPI plugin, a Go library built with `-buildmode=c-shared`. `make -C plugin build` writes `.target/dist/oneclaude-v<version>.dylib`, and `make -C plugin test` runs its tests.
- The proxy loads a plugin from `<plugins.dir>/darwin/arm64/<id>-v<version>.dylib`, and the plugin id `oneclaude` comes from that file name. A plugin with no `plugins.configs.oneclaude` block in the proxy config stays off.
- The proxy picks up a new plugin file only on a config reload or a restart, and then hot reloads it with no dropped reply. It deletes older versions of a plugin's file at startup. Never overwrite a loaded library in place: copy the new build under a new version name.
- The proxy loads the version `plugins.configs.oneclaude.store.version` names, as its Plugin Store does. cmod runs `setup/install.sh` on install and on every new version: it builds the plugin, then `plugin/cmd/install` copies it into the proxy's plugin folder and sets that key, so a version bump in `plugin/main.go` and `.claude-plugin/plugin.json` together, then `cmod link .`, takes a build live.
- `plugin/cmd/install` finds the proxy config from the `-config` of the process on `ANTHROPIC_BASE_URL`'s port, else Homebrew's `etc/cliproxyapi.conf`, and rewrites only the config's `plugins` and `management` blocks, leaving every other byte as it was. With no proxy found, it installs CLIProxyAPI with Homebrew, sets its `server.host` to `127.0.0.1`, drops the example's placeholder `access.api-keys`, and starts it with `brew services`.
- `plugin/cmd/install` sets the proxy's management key to `oneclaude`, written as its bcrypt hash so the proxy never rewrites the config, and keeps the key it replaced in `management-key-was` in the mod's data folder for `--remove` to put back. It copies the account Claude Code is logged in to, read from `~/.claude.json` and the keychain item `Claude Code-credentials`, into the proxy's auth dir as the credential file the proxy's own login writes, unless a credential there has that email.
- The mod sets `env.ANTHROPIC_BASE_URL` with cmod 1.6.0's `settings.user.update`, a JSON Merge Patch that leaves every other `env` value, once a session after the proxy answers with oneclaude's status. cmod takes back only that value at removal. A base URL the person set to another address stays.
- The plugin reads each Codex account's weekly usage from `chatgpt.com/backend-api/wham/usage`, the window whose `limit_window_seconds` is a week, and `status.json` lists Codex accounts in `codex`, apart from the Claude pool it routes.
- Claude Code 2.1.301 strips every private-use character, U+E000 to U+F8FF, from the text a mod draws, so Nerd Font glyphs never show.
- The proxy consults only one scheduler plugin, the first by priority and then by id, so Seat Pacer must be off for oneclaude to route.
- `plugin/main.go` and `plugin/internal/runtime/{wire,envelope,host}.go` adapt Seat Pacer's MIT-licensed C boundary, credited in `plugin/NOTICE`.
- The plugin serves its status without a key at `/v0/resource/plugins/oneclaude/status.json`, with account names cut to the local part of their address.
- The plugin serves `plugin/internal/runtime/dashboard.html` at `/v0/resource/plugins/oneclaude/dashboard`, its only resource with a `Menu`. The panel orders a plugin's menu entries by path, so `management.html#/plugin-pages/oneclaude/0` shows the dashboard in an iframe of the same origin. Its Content-Security-Policy names the hash of the page's one `<script>` block, computed when the plugin loads.
- `/v0/resource/plugins/oneclaude/history.json` serves each account's requests per hour for the last 7 days. The first read takes the lines earlier loads wrote to `requests.jsonl`, read back from its end, and every request since the load counts as it happens.
- The dashboard reads oneclaude's routes without a key and the panel's `/v8/management` API with the management key the panel saves in `localStorage` under `cli-proxy-auth`, or else `oneclaude`. The proxy bans an address for 30 minutes after 5 failed key checks, so the page stops at the first refusal.
- `dashboard?open=<section>`, opened on its own, saves the panel's login with the key `oneclaude` as the panel's Remember password does, then opens the panel at the dashboard, which scrolls to `<section>`. The section travels in `sessionStorage`, because the panel passes through its login route while it signs in and drops the address's query.
- The plugin keeps `usage.json`, `limits.json`, `agents.json`, `install.key`, and `requests.jsonl` in `~/.cli-proxy-api/plugins/oneclaude/`, or in its `data-dir` setting. `agents.json` holds each conversation's account, so a reload keeps its cache.
- The repository root is a cmod mod: `src/mod.tsx` is the `defineMod`, `hooks/register.ts` only registers it, and `tests/` holds its `bun test` suite. `node_modules/@cmodjs/core/docs/` is the cmod documentation for the installed version.
- `cmod check .` runs every check on the mod. It skips `.target/`, so every build output and the dev proxy live there.
- The dev proxy is CLIProxyAPI v8.0.0 built from source into `.target/dev/cliproxyapi`, run with `dev/config.yaml` on port 8318 against `plugin/cmd/fakeanthropic` on port 8319. `ONECLAUDE_DEV_PROXY=1 go test -run DevProxy` in `plugin/` checks routing through it, and its subagent test needs 5 minutes since the last run, while the earlier run's agents still count as active.
- The dev proxy serves its management panel only when it starts with `MANAGEMENT_PASSWORD` set, and downloads `management.html` into `.target/dev/static/` on the first visit.
- The live proxy on port 8317 serves the Architect's running agents. Plugin builds go to the dev proxy first.
